# 路线图

## 指导原则

每一版只回答**一个问题**。答不出来就不做。功能列表不是路线图。

---

## ✅ v0.1 — MVP（当前）

**问题：把一天的对话沉淀成记忆之后，电脑前的 AI 是否真的能少问我几句话？**

已交付：

- [x] 异步管线：上传 → ffmpeg 归一化 → faster-whisper → 说话人归属 → LLM 因果蒸馏 → 入库
- [x] 三种上传方式：multipart / 裸 body / 分片续传，全部按内容 SHA-256 幂等
- [x] 因果蒸馏输出结构化的 `cause → effect` 边、决策、承诺、事实、实体
- [x] 上下文卡片 `build_brief()`，按 token 预算从尾部整段截断
- [x] `causal-memory` 集成（Python 绑定），带 `native` SQLite 自动降级
- [x] `ss` CLI：`brief` / `commitments` / `search` / `timeline` / `upload` / `status`
- [x] `ss inject`：把卡片写进 Cursor / CLAUDE.md / AGENTS.md / Copilot / Windsurf / Cline
- [x] MCP server（stdio），5 个工具 + 2 个资源
- [x] 声纹录入 API 与主观/客观二分归属
- [x] Docker Compose 单卷部署 + `shadowscribe doctor`
- [x] 中文优先的文档：README、架构、接入协议、记忆模型、部署

**刻意不做**：实时语音、声纹指令拦截、执行器、端侧加密、多方聚类。
理由见 [architecture.md §4.1](architecture.md#41-为什么用异步而不是实时)。

## 🚧 v0.2 — 让记忆自己闭环

**问题：记下来的承诺，能不能自己变成"已完成"？**

- [ ] **承诺自动闭环**：从后续对话里识别"那个事儿我搞定了 / 已经发你了"，
      自动把对应 `commitment` 置为 `done`
- [ ] **多方说话人聚类**：不止"主人/对方"，用 sherpa-onnx 聚类出 `说话人1/2/3`，
      并在多次出现时保持稳定 ID
- [ ] **实体消歧**：`老王` / `王工` / `王总` 归并；跨天追踪同一项目的全部脉络
- [ ] **写边幂等**：让 `reprocess --index-memory` 不再重复写入（按
      `(cause, effect, task_tag)` 去重）
- [ ] **`ss watch`**：常驻终端小面板，显示队列深度与最新流入的记忆

## 🔜 v0.3 — 降低成本与摩擦

**问题：能不能无感地跑一整周？**

- [ ] **端侧 VAD 与省流量上传**：手机端只上传有语音的片段（服务端协议已支持
      `chunk_index`，需要手机端配合）
- [ ] **增量转写**：长录音边传边转，而不是等整个文件传完
- [ ] **本地 ASR 兜底**：允许接入局域网内的 Ollama / vLLM / whisper.cpp，
      让对隐私极敏感的用户完全不出网
- [ ] **时间轴可视化**：一个只读的静态 HTML，把某天的因果图渲染出来
- [ ] **记忆编辑**：修正抽错的边、合并重复的承诺

## 🔮 v0.4 — 状态 B：声纹授权执行

**问题：用主人的声音下达指令，能不能安全地唤醒执行器？**

- [ ] 常驻声纹监听（端侧，只在检测到主人声纹时上行）
- [ ] 指令动词识别 + 置信度阈值双闸
- [ ] 执行器抽象层（创建 Issue / 跑脚本 / 发消息），全部走白名单
- [ ] 完整的审计日志：每一次"打破静默"都可追溯到音频片段与声纹得分
- [ ] **默认关闭**，需要显式开启并二次确认

> 这一版的风险等级和前三版完全不同。任何"AI 替主人做了事"的能力，
> 都必须先有可回滚、可审计、可一键断电的设计。

## 不在计划内

明确说明，避免期待落空：

- **主动提醒 / 通知 / 弹窗**——违反原则一。影书永远不会主动找你。
- **对话式问答机器人**——市面上已经够多了，且它的价值在于"被问"，而影书的
  价值在于"你不需要问"。
- **云端多租户 SaaS**——本项目定位是"你自己的外脑"，跑在你自己的机器上。
- **情绪分析 / 人格画像**——技术上可行，但把它用在同事和客户身上是越界的。
